SECTION 01

なぜ HTML なのか

AI の得意分野で勝負する

PowerPoint と HTML を比べると

PowerPoint を AI で作る

  • 中身は XML、細かい制御が苦手
  • 画像だけのスライドになりがち
  • アニメーションは思い通りにならない
  • 差分が見えず、修正指示が通りにくい

HTML / CSS / JS を AI で作る

  • 学習データが膨大で、意図どおりに書ける
  • 本物のコード・図・デモを動かせる
  • アニメーションを細かく制御できる
  • テキストなので Git で差分管理できる

左右のカードがステップで順に出る。

ポイント: 「人が PPT を覚える」より「AI の得意な形式に寄せる」方が安い。

SECTION 02.5

動く図の部品

AI は JSON を書くだけ。描画・動き・クリックは部品が担当

注文 API の流れを、→ キーで順に追う

→ キーで経路がハイライトされ、矢印上を点が流れる。ノードをクリックすると詳細パネル。

全体図から、クリックで中身にズームする

「注文システム」をクリック (または →) で中にズームし、中のノードもクリックできる。Esc か背景クリックで全体に戻る。

大きなシステムは、階層をたどって細部へ入る

中身のある箱 (重なった箱) をクリックで中へ。左上のパンくず、Esc / Backspace で上の階層へ戻る。端の点線の箱をクリックすると、そのシステムへ移る。右下の「流れ」で業務の流れを選び、▶ で 1 区間ずつ追える。

注文の状態は、遷移させて確かめる

状態遷移図は "simulate": true で、今の状態から出ていける遷移がボタンになる。外側の状態 (注文済み) に書いた遷移は、中のどの状態からでも使える。

ER 図はデータから自動で配置する

テーブルをクリックすると関連テーブルと結合キーが光る。

シーケンス図は 1 手ずつ再生する

グラフは伸びて、凡例で切り替えられる

レイヤー構造を 3D で分解して見せる

プレゼンテーション層
アプリケーション層
ドメイン層
インフラ層

→ キーで分解。ドラッグで回転、層をクリックで説明。

ビフォー・アフターは境界をドラッグして比べる


              function total(items) {
                let sum = 0;
                for (let i = 0; i < items.length; i++) {
                  if (items[i].active == true) {
                    sum = sum + items[i].price * items[i].qty;
                  }
                }
                return sum;
              }
            

              const total = (items) =>
                items
                  .filter((item) => item.active)
                  .reduce((sum, { price, qty }) => sum + price * qty, 0);

ループと一時変数がなくなり、意図が読める

→ キーで改善後へスライド。境界はドラッグで動かせる。

コマンドの実行を、その場で再生する

→ キーでコマンドを 1 つずつ入力して実行結果を表示する。
