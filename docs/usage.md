# 依頼のしかた (使う人向け)

jh-presentation を MCP サーバーとして登録した AI クライアントに、プレゼン資料の作成を頼むときのガイドライン。
AI 向けのスライドの書き方は [authoring-guide.md](authoring-guide.md) にある (AI が自分で読む)。

## 基本: 「jh-presentation で」と最初に一言付ける

```
jh-presentation で、Git の基本を新人向けに 15 分で説明するプレゼン資料を作って
```

道具の名前を書かなくても伝わるクライアントは多いが、一言付けるとどのクライアントでも確実に jh-presentation が使われる。

| クライアント | 名前を書かない場合 | 補足 |
|---|---|---|
| Claude Code / Claude Desktop | ほぼ伝わる (「プレゼン資料」「スライド」で選ばれる) | コードのプロジェクトでは HTML を自分で書き始めることがある。プロジェクトの `CLAUDE.md` に次の 1 行を書いておけば毎回書かなくてよい |
| GPT (ChatGPT / Codex) | 伝わりにくい | 組み込みのプレゼン機能 (PowerPoint など) が優先されがち。**必ず名前を書く** |
| jh-ai-agent | 「プレゼン資料」「スライド」を含めば伝わる | 依頼文の言葉で MCP の道具を選ぶ。`jh-presentation` と書けばすべての道具が渡る |

プロジェクトの `CLAUDE.md` / `AGENTS.md` に書いておく 1 行:

```
プレゼン資料・スライドは jh-presentation MCP で作る (自分で HTML を書かない)。
```

## 依頼文に入れるとよいこと

| 項目 | 例 | 書かない場合 |
|---|---|---|
| 目的・聞き手 | 新人エンジニア向けの勉強会 | 一般的な社内向けとして作る |
| 持ち時間 | 15 分 | 10 分程度 (本編 6〜8 枚) |
| 伝えたいこと | 「add と commit の違いが分かる」 | 内容から AI が決める |
| 見た目 | テーマ `dark` / 演出は控えめ | 内容に合わせて AI が選ぶ |
| 元にする資料 | ファイルのパス・URL・箇条書き | AI の知識で書く (数値は創作しないので、使う数値は渡す) |
| 出力 | PDF も欲しい | HTML 1 ファイルだけ (そのまま配布・発表できる) |

長い発表や方向性が曖昧な依頼では、AI が先に構成案を出して確認を求める。構成案の段階で直すのが一番早い。

## 決まった型で頼む (テンプレート)

技術解説・LT・進捗報告・技術提案は、依頼文テンプレートを使うと構成と演出が揃う。
Claude Desktop は入力欄の「＋」、Claude Code は `/mcp__jh-presentation__tech-talk` のように選ぶ ([prompts/README.md](../prompts/README.md))。

## 作った後の直し方

- **誤字や言い回し**: ブラウザでデッキを開き、枠のダブルクリック (または E キー) で直して Ctrl+S。AI に頼まなくてよい
- **構成や図**: 「3 枚目の図を、注文から発送までの流れにして」のように、スライドの番号か内容を指定して AI に頼む
- **崩れていたら**: 「崩れを直して」と頼む。AI は書き込むたびに自動検査の結果を受け取っているので、多くはその場で直る
- ブラウザの「名前を付けて保存」は使わない (デッキが壊れる。壊れた場合は「デッキを復旧して」と頼む)

## モデルによる差について

画像を見られないモデル (DeepSeek など) は、スクリーンショットで見た目を確かめられない。
そのため jh-presentation は、書き込むたびにはみ出し・重なり・小さすぎる文字などを自動で検査して AI に返し、
ガイドに「良い例」と「崩れやすい書き方」を載せている。それでも気になる崩れがあれば、スライドの番号を添えて直しを頼む。
